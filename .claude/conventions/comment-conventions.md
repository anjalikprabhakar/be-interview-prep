# Comment conventions

These apply to every changed line in a PR: code comments, Javadoc, SQL comments, and test comments. The goal is code you can explain in an interview without the comments lying to you.

## Rules
1. **Explain *why*, not *what*.** The code already says what it does. A comment earns its place by giving the reason, constraint, or trade-off.
   - ✅ `// Atomic conditional UPDATE: the row lock makes check-and-decrement one step, so stock can't go negative.`
   - ❌ `// decrement stock`
2. **Comment the load-bearing line.** Wherever correctness depends on a single line (a conditional `UPDATE`, `updatable = false`, `@Transactional`, a UNIQUE constraint, `SessionCreationPolicy.STATELESS`, a cache evict), put a one-line comment saying what breaks without it.
3. **Don't restate names.** Avoid `// get the task` above `getTask()`, or Javadoc that just repeats the method signature.
4. **No commented-out code.** Delete it, because Git keeps the history.
5. **No bare TODO or FIXME.** Every one must reference an issue (`// TODO(#12): …`), or it gets resolved before merge.
6. **No meta or AI comments.** Leave out "as requested", "generated by", "Claude", "the user wants", or notes addressed to a reviewer. Comments are for future readers of the code.
7. **Keep comments true.** A comment contradicted by the code is a defect (review-conventions.md B10). When you change the code, update or delete its comment in the same commit.
8. **Javadoc only where it adds information.** Use it on public types or methods whose contract isn't obvious (for example `ApiError`, which is "the single JSON error shape returned by every endpoint"). Skip it on trivial getters and constructors.
9. **Tests:** comment non-obvious setup, such as why a `CountDownLatch` start gate exists, or why a test is *not* `@Transactional`. Don't narrate the given/when/then steps.
10. **Style:** English, full sentences, with sentence case and a full stop for multi-word comments. Use `//` for single lines and `/** */` only for Javadoc. Keep lines within 120 characters.
